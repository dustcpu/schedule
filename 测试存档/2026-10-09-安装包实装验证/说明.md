# 2026-10-09 安装包实装验证：v0.1.11 能否正常安装与卸载

## 为什么要测
用户最担心的是「**安装包装在别人电脑上能不能装成功**」（v0.1.0~v0.1.10 的安装包
因为找不到引擎而完全不可用，v0.1.11 才修）。而安装动作本身（落盘、注册表、快捷方式、
卸载）只有真装一遍才能验，因此经用户授权在本机实装一次。

## 方法（全程隔离，不碰用户数据）
1. 先记录基线：安装目录 / 注册表卸载项 / 开始菜单项 —— **安装前都不存在**
2. 把 `%APPDATA%\排课助手` 整体改名 → `排课助手.bak_20261009b`（隔离，避免启动时读用户的历史文件）
3. **静默安装**：`排课助手_0.1.11_x64-setup.exe /S`
   （用 Python `subprocess` 调用，避开 Git Bash 对 `/S` 的路径转换）
4. 测试用 `config.json`：`last_input_file` → 仓库合成数据；`default_output_dir` → `%TEMP%\paike_inst_test_out`
5. 装完启动、看日志 → **卸载** → 恢复配置

### 卸载
`uninstall.exe /S` → 退出码 0，耗时 1.4 秒。之后复查：
- 安装目录 **已删除** ✓
- 注册表卸载项 **已清除** ✓
- 开始菜单 + 桌面快捷方式 **已清除** ✓
- ⚠️ **厂商键 `HKCU\Software\Dust.\排课助手` 残留**（Tauri 的 NSIS 模板只删
  `Uninstall\<产品名>`，不删厂商键——该键用于记录安装位置供下次安装复用）。
  影响很小（一个只存路径的空键）。**本次测试产生的该键已手工删除。**

## ⚠️ 两点与沙箱有关、**不要误判为缺陷**
1. **引擎启动极慢**：直接跑 `engine.exe --validate` 用了 **205 秒**，GUI 里的预检用了 **188.6 秒**。
   原因是沙箱环境启动 105 MB onefile 的固定开销（CPU/IO 竞争）。
   **真机对照**：用户 2026-10-09 便携版实测，同一件事只用 **6.6 秒**。
   → **永远不要用沙箱耗时判断"卡死"或"性能问题"。**
2. 曾出现「日志只有 `[预检] 开始`、没有 `[预检] 结束`」，一度以为是第二个 bug。
   实际上是**我 kill 进程太早**（等了 150s / 300s，不够 188s）。用 20 秒间隔采样进程才看清：
   `engine.exe` 被正常拉起、跑了约 3 分钟后自行退出。

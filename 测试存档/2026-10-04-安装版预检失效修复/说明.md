# 2026-10-04 输入预检在安装版必定失败

> 现象：开发版（`启动-测试.bat` → `cargo run`）一切正常，**装到用户机器上**
> 选完输入文件后的「输入文件检查」永远失败；「用 AI 转」也因为拿不到姓名/班级清单
> 而拒绝生成提示词。

---

## 1. 结论先说

**不是数据问题，是外壳调用校验脚本的方式在安装版根本不成立。**

`src-tauri/src/main.rs` 的 `validate_input` 原先写死两件事：

```rust
let manifest_dir = env!("CARGO_MANIFEST_DIR");            // ← 编译期常量
let script = Path::new(manifest_dir).join("../engine/validate_input.py");
Command::new("python").arg(&script) ...                    // ← 系统 python
```

- `CARGO_MANIFEST_DIR` 是**编译那一刻**的源码目录（开发机的
  `E:\schedule software\排课助手-github\src-tauri`）。安装到别的机器后，
  这个路径**并不存在**。
- 即便路径存在，用户机器上**也没有 Python**，更不会有 openpyxl。

所以这条路径属于"开发机能跑、发布版必挂"——而且因为它**静默**返回
`无法运行校验脚本`，很容易被当成"用户数据有问题"。

---

## 2. 修法

把校验能力**并进引擎**，做成子命令：

```
engine.exe --validate <输入.xlsx>      # stdout 只输出一行 JSON
```

- 外壳改用 `build_engine_command()`（与排课**同一套**引擎定位逻辑：
  `resource_dir/engine/engine.exe` → dev 的 `src-tauri/resources/engine/engine.exe`
  → 源码 `../engine/engine.py`），再追加 `--validate <path>`。
- 引擎 exe 里本来就有 **openpyxl**（导出 xlsx 要用），所以用户机器**不需要装 Python**。
- 开发版和安装版走的是**同一条代码路径**，不会再有"只有打包后才暴雷"的问题。
- 子命令分流放在 `main()` 最前面（版本号打印之前）—— stdout 只能是那一个 JSON，
  混进版本行外壳就解析不了。

改动清单：

| 文件 | 改动 |
|---|---|
| `engine/engine.py` | 新增 `_emit_json()` / `_run_validate()`；`main()` 开头按 `--validate` 分流 |
| `engine/build_exe.py` | 加 `--hidden-import validate_input`（见下） |
| `src-tauri/src/main.rs` | `validate_input` 改为 `build_engine_command()` + `--validate` |

⚠️ **两个必须踩对的点**

1. **必须重新打包**：改的是引擎源码，外壳调用的是 `engine.exe`，不打包等于没改。
   `cd engine && "D:\python\python.exe" build_exe.py`，再把
   `engine/dist/engine.exe` 复制到 `src-tauri/resources/engine/` 与
   `src-tauri/target/debug/resources/engine/`。
2. **`--hidden-import validate_input` 不能省**：`engine.py` 只在 `_run_validate()`
   的函数体里 import 它，PyInstaller 的静态分析未必收得到。漏了它，**开发版照样正常**
   （直接跑 `.py`），只有打包版报 `ModuleNotFoundError` ——
   又是一个"只有打包后才暴露"的坑。

## 3. 验证

```bash
cd engine
# 源码版
"D:\python\python.exe" engine.py --validate test_input_25_new/input.xlsx
# 打包版（真正要验的那条）
./dist/engine.exe --validate test_input_25_new/input.xlsx
```

期望（用仓库合成数据 `engine/test_input_25_new/`，占位命名）：

- 正常输入 → `{"valid": true, ...}`，`stats` 里 `teachers=93 / classes=25 / subjects=15`，
  且 `teacher_map` 93 条、`class_map` 25 条（前端脱敏靠它）；
- 文件不存在 → `{"valid": false, "errors": ["文件不存在"], ...}`，退出码 0；
- 不带参数正常调用 → 仍打印 `排课引擎 v0.1.7` + 用法行，**排课主流程不受影响**；
- stdout 是**单个** JSON 对象，中文不乱码（`"新格式（课时标准）"`）。

一次跑完三种情况：`python 复现脚本/validate_probe.py`
（加 `--exe` 则用打包后的 exe 跑，较慢）。

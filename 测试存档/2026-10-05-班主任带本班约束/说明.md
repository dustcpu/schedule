# 2026-10-05 新约束 H29：班主任必须教自己带的班

> 需求原话：**"班主任必须教自己带的班"** —— 比如一位英语老师当了班主任、要教 2 个班，
> 其中一个必须是他自己当班主任的那个班。
> 做法：设置页「班级设置」加一个开关，勾上后上面这条成为硬约束（**班会的固定课不算**）。默认关。
>
> 等价说法（引擎里就是这么写的）：对每个班 C，其班主任 T 必须教 C 的某一门正式课，
> 即 `Σ_s y[C, 学科 s, T] ≥ 1`。两者是同一件事——「他教的班里有一个是自己的班」
> ⟺ 「他必须教自己的班」。

---

## 1. 一个前提事实：这列以前引擎没读过

「班级」sheet 的「班主任」列**一直都在模板里**（`make_sample_input.py` 会写、
`input_template.md` 有说明），但 `load.py` 的 `ClassInfo` 只取了
`id / name / grade / elective` —— **`班主任` 从头到尾没被解析过**。
所以这不是"加一个开关"，而是要先把这列读进来，再补建模与校验。

同时这也意味着：**校方表里如果这一列没填，功能就是空转**（不报错，但不生效）。
本次实现里，没填的班直接跳过（不告警），填了但认不出的才告警。

## 2. 为什么不需要新建模

问题清单 2026-10-01 的 **2b**「某教师的班必须包含某班」当时判定为"需要新建模"，
是因为把它当成**通用**约束（任意教师 × 任意班级）来做。

但本需求是它的**特例**：班级表里已经写明"谁是班主任"，所以「哪个教师、哪个班」
是**数据给定的**，不引入新决策。而教师分配 `y[班级, 学科, 教师]` 自 2026-09-28
起就已经是决策变量（H25/H26 那一批），于是约束就是一行：

```
Σ_s y[班级, 学科, 班主任] ≥ 1
```

**代价**：班主任必须出现在「本班 + 他任教学科」那门课的候选集里，
否则模型里没有可用的 0/1 变量。所以加载层要多做一步"补候选"。

## 4. 实现上的几个判断

- **不覆盖用户意图**：若该课已被「特殊要求」显式指定给别人（`course.locked`），
  **不覆盖**，而是把该班列入"不适用"并说明原因。
- **不制造无解**：班主任在本班没有任教科目（该学科周课时为 0）、或该课被别人锁定、
  或教师表里查无此人 —— 一律**跳过 + 逐类告警**，绝不因此把整表判成 INFEASIBLE。
- **ID 容错**：该列写 `T001`、写 `T01`、写姓名「语文老师001」都能认（复用既有
  `_resolve_id` + 姓名反查）；认不出的已归一为""，避免下游重复告警。
- **默认关**：不勾选时 `homeroom_must_teach_own = False`，建模层与加载层都不动作，
  行为与旧版**逐字节一致**（可对比约束数）。

## 5. 验证（都实测过）

用仓库合成数据 `engine/test_input_25_new/`（25 个班，班主任 C01..C25 → T001..T025）：

| 项 | 结果 |
|---|---|
| 开关关 | 无 H29 约束、无相关告警；约束数 109549 |
| 开关开 | +25 条（每班一条）；告警「班主任必须教自己带的班：已生效 —— 25 个班的班主任都排到了本班的正式课」；约束数 109574 |
| 端到端求解 | FEASIBLE，3 套方案，总耗时 **182.4s**（改动前基线约 184s，无退化） |
| 交付课表复核 | `verify_hard.py <in> --xlsx <result.xlsx>` 三套方案 H1–H5 全过；另行逐班核对 H29：**3 套方案 × 25 班全部满足**（如 C01 班主任 T001 在本班教语文） |
| 边界 | 该列写姓名 → 能解析；写 `T999` → 告警"在教师表里找不到"；留空 → 跳过 |

快速复跑（秒级，不进求解）：`python 复现脚本/homeroom_probe.py`

## 6. 顺手记一条：一个坑的对称项

`ClassRule` 加字段时必须写 `#[serde(default)]`。否则老用户的 `config.json` 里
没有这个字段 → 整个 `Config` 反序列化失败 → `load_config()` 走
`unwrap_or_default()`，**用户此前所有设置（输出目录、连堂日、固定课…）被静默重置**。
（`SolverConfig.only_core_subjects` 当初就是这么写的，本次沿用同一手法。）

> 这也解释了一个"以前踩过"的同类问题：只要给持久化结构加**必填**字段，
> 就必须同时考虑"旧文件怎么办"。加 `#[serde(default)]` 是最小代价的兼容。

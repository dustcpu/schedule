# 2026-10-09 便携版实测：确认「安装版布局能找到引擎」（替代安装测试）

## 为什么要测
v0.1.11 修的是「安装版找不到排课引擎」（自 v0.1.0 起一直存在）。
用户不想在这台电脑上装安装包（怕影响现有环境），因此**用便携版等价验证**。

**为什么等价**：v0.1.11 修完之后，便携版与安装版的文件布局**完全一致** ——
两者都是 `<exe所在目录>\resources\engine\engine.exe`。安装包（`installer.nsi` 的
`Section Install`）铺的正是 `$INSTDIR\resources\engine\engine.exe`。
所以「能不能找到引擎、能不能排课」这一层，便携版测出来等价于安装版。

## 测试环境
- 程序：`E:\schedule software\_便携版测试\排课助手-便携版\`（从
  `发布包\发给教务老师\4-备用-便携版-v0.1.11.zip` 解压）
- 输入：`engine\test_input_25_new\input.xlsx`（仓库自带合成数据，占位名）
- 输出：`E:\schedule software\_便携版测试\输出`
- 隔离：测试期间把 `%APPDATA%\排课助手` 改名为 `.bak_20261009`，
  使程序以「全新用户」状态启动（配置为空 → 不会去预检任何历史输入文件）。

## 结果：全部通过

### ① 引擎定位（本次修复的核心）
外壳日志第 3 行：
```
[22:12:01.716] 排课引擎: \\?\E:\schedule software\_便携版测试\排课助手-便携版\resources\engine\engine.exe
```
→ 命中的是**程序自己目录下的** `resources\engine\engine.exe`，
不再是开发机上的源码路径。**修复生效。**

### ② 输入预检（安装版此前连这一步都失败）
```
[22:12:41.580] [预检] 开始: ...\test_input_25_new\input.xlsx
[22:12:48.208] [预检] 结束: 耗时 6.6s, 有效=true, 错误 0 条, 警告 1 条

```
→ 真机耗时 **6.6 秒**（沙箱里同样操作要 60+ 秒，那是沙箱启动 105MB onefile 的固定开销）。

- 测试结束的 `config.json` 里 `last_input_file` 指向**合成数据**，
  `default_output_dir` 指向测试输出目录 → **整个过程没有触碰任何禁区文件**

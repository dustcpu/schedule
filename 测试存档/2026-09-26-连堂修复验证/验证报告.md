## 4. 修复内容

### 4.1 H5b —— 非指定日不得相邻排课

`engine/scheduler/solver/model.py`

```python
# 修改前：把连堂学科整个跳过
for (cid, s), blen in block_len_of.items():
    if blen > 1:
        continue          # ← 语数英被跳过，非指定日完全不受约束
    ...

# 修改后：连堂学科仅在指定日豁免
for (cid, s), blen in block_len_of.items():
    if s == SELF_STUDY:
        continue
    desig = consec.day_of(s) if blen > 1 else None
    for d in days:
        if desig is not None and d == desig:
            continue      # 指定日交给 H5
        for per in range(1, n_per):
            model.Add(x[(cid, s, d, per)] + x[(cid, s, d, per + 1)] <= 1)
```

**问题**：`blen > 1` 的学科被整条跳过，而 H5 只管指定日 —— 语数英在其余四天
完全不受约束，求解器会在别的天再排一个双节连堂（实测 146 处）。

### 4.2 H5c —— 非指定日每天至多 cap 节

只禁相邻后，语数英余下课时仍会挤在少数几天（实测 319 处"某天两节、另一天零节"）。
新增约束：

```
cap = ceil((周课时 - 连堂块节数) / 非指定日天数)
```

**`cap` 按周课时推算而非固定为 1，是为保证永远可行**：

| 语数英周课时 | cap | 结果 |
|---|---|---|
| 6 节/周 | 1 | 每天恰好一节 + 指定日连堂 |
| 7 节/周 | 2 | 仍可行，同时在 `warnings` 中如实告警 |

> 若写死 `cap = 1`，7 节/周会直接 `INFEASIBLE` —— 一张课表都排不出。

**护栏验证**：构造 25 班语数英各 7 节/周的数据实测，结果
`code=1、5 套方案、25 条 warning`，如：

```
班级 C01 的「数学」周课时 7 节，扣除连堂 2 节后仍有 5 节，
无法做到其余每天至多 1 节（已放宽为每天至多 2 节）
```

### 4.3 连堂位置收窄为 1-2 节或 4-5 节

`engine/scheduler/config.py`

```python
# 修改前：[1, 2, 3, 4]  → 允许 1-2 / 2-3 / 3-4 / 4-5
# 修改后：[1, 4]        → 只允许 1-2 / 4-5
allow_start_periods: List[int] = field(default_factory=lambda: [1, 4])
```

**依据**：一位老师通常带 2 个班，一个班排上午 1-2 节、另一个班排上午 4-5 节，
两班错开便于教师连堂授课 —— 这正是 `hard_limits`「连堂规则」一栏描述的原始意图，
此前实现比设计意图宽松。

> 该参数目前是内核默认值，**外壳设置页尚未开放配置**。

## 5. 遗留问题（**未修复**）

### 5.1 多解多样性不足 —— 随约束收紧持续下降

| 版本 | 25 班两两差异（max） |
|---|---|
| 基线 `a0b072d` | 49.6% |
| `c007f98` | 1.16% |
| **本次 `1d77175`** | **0.58%** |

每加一条约束，可行解空间就进一步收窄，naïve no-good 能"自由发挥"的余地更小。

这印证了 2026-09-25 分析报告的判断：**naïve no-good 的多样性本就是碰运气**。
彻底解决需改为**差异化权重法**（独立压测验证：同样规模下可达 **86%** 差异度）。

### 5.2 评分与命名无区分度

5 套方案的 `score` 仍全为 `100.0`，`note` 描述文字完全相同，
方案名仍按序号硬分配（`PLAN_NAMES[(i-1) % len]`）。

详见 `../2026-09-25-引擎问题分析/分析报告.md` §4。

# 2026-10-03 取消排课 + 窗口记忆

> 本次改动：给排课加「取消排课」按钮，并修好两个一直没生效/会误导的界面行为。
> 这里只记录**需要实测才能确认**的部分与验证方法；界面的样式收敛不在此列。

---

## 1. 为什么会有这一轮

用户实测后的原话是三个诉求：**① 排课中途想放弃只能关窗口**（而关闭默认收进托盘，
进程还占着 CPU，不知道的人会以为程序卡死）；**② 失败后拿不到现场**，只有一句
「排课失败」；**③ 窗口大小/位置记不住**，每次打开都回到默认尺寸。

这三件事里，① 和 ③ 都不是"加个按钮"那么简单 —— 它们各自踩到一个不明显的机制上。

## 2. 取消排课：为什么不只是 `child.kill()`

### 现象
点「开始排课」后要等约 3 分钟（25 个班）。中途没有退路。

### 实测发现（这是本轮最重要的结论）

`engine.exe` 是 **PyInstaller onefile**。在 Windows 上它不是单进程，而是
**两个进程**：

```
bootloader 父进程（负责解包）  →  子进程（真正在跑 Python 求解）
```

实测证据（`cancel_probe.py` 输出）：

```
杀掉之前：engine.exe 进程 = ['35672', '36148'] （共 2 个）
执行 taskkill /F /T /PID 36148
  成功: 已终止 PID 35672 (属于 PID 36148 子进程)的进程。
  成功: 已终止 PID 36148 (属于 PID 4256 子进程)的进程。
taskkill 后 engine.exe 进程：无
```

两条直接推论：

1. **必须 `taskkill /F /T`（`/T` = 杀整棵树）。**
   只终止父进程的话，子进程会**继续算下去** —— 用户以为取消了，实际还在占 CPU，
   而且不会有任何提示。
2. **强杀一定留下垃圾。** 被强杀的进程来不及执行自己的清理逻辑，
   `%TEMP%` 下的 `_MEIxxxxxxx` 解包目录会留下来。实测：

   ```
   新增 _MEI 解包目录：['_MEI00008d342']
       合计约 243.9 MB
   ```

   约 **244 MB / 次**。所以外壳必须兜底清理，见下。

### 实现

| 位置 | 做法 |
|---|---|
| `main.rs` `running_pid_slot()` | 引擎起来后登记 PID，供取消时定位 |
| `main.rs` `cancel_scheduler` | 置取消标志 + `taskkill /F /T /PID <pid>` |
| `main.rs` 轮询循环 | 每次也检查取消标志；taskkill 失败时用 `child.kill()` 兜底 |
| `main.rs` `cleanup_mei_leftovers(since)` | 删 `%TEMP%` 下名字以 `_MEI` 开头、且 mtime 不早于任务开始时刻的目录（上限 5 个，防误删） |
| `main.rs` 收尾 | 取消时返回 `code=2` + message 以「已取消」开头；清工作目录 |
| `ui/index.html` | 排课中显示「取消排课」；结果以「已取消」开头时用**中性样式**，不当成失败 |

> 时间窗过滤（`since`）是为了不误伤同时运行的其它 PyInstaller 程序；
> 数量上限是异常情况下的保险。

## 3. 窗口记忆：又一个「ACL 静默拒绝」

### 现象
`%APPDATA%\排课助手\config.json` 里的 `window_state` **一直是 `null`** —— 这个功能从上线起就没生效过。

### 根因
原先在前端调 `getCurrentWindow().outerSize()` / `outerPosition()`。
那是 Tauri **core** 的 window API，而本项目 `src-tauri/capabilities/` 目录
**不存在** → 调用被 ACL 拒绝；更麻烦的是**前端用的是 `try/catch` 吞掉异常**，
所以既没有报错也没有效果，只是"什么都没发生"。

这是同一个坑的第三次踩到（前两次：`event.listen` 进度事件、以及其它 core API）。

### 修法
搬到 Rust 侧，**不经过 ACL**：监听 `WindowEvent::Resized` / `Moved`，
直接用 `win.outer_size()` / `outer_position()` 读值写配置。
拖动时事件每帧都触发，因此加了 800ms 防抖（`should_save_window_state()`）；
最小化与「负得离谱的坐标」都挡掉，避免把最小化状态存成窗口尺寸。

> ⚠️ **这条无法自测**：需要真 GUI。请在界面上拖动/缩放窗口 → 关闭程序 → 重新打开，
> 看位置和大小是否记住。若没记住，说明 `Resized/Moved` 事件在本环境没触发，
> 需要换回「启动时读配置 + 定时保存」的方案。

## 4. 另外两处

- **失败时露出一个空的「结果文件」区**：`renderResult` 无条件显示结果区，
  而失败/取消时既无方案也无文件 → 页面上只剩一个标题加一片空白。现在没有内容就不显示。
- **失败时没有出口**：新增「打开日志文件夹」，
  直接打开 `%APPDATA%\排课助手\logs\`（里面是外壳保留的 `<任务ID>.engine.log`）。

## 5. 验证

`cancel_probe.py`（本目录）**只读仓库、只在系统临时目录写东西**，可重复运行：

```bash
python cancel_probe.py        # 约 2 分钟（沙箱环境含解包开销）
```

它会启动真实引擎 → 等到出现两个进程 → `taskkill /F /T` → 报告进程是否清空、
`_MEI` 残留多大。

本轮其余验证：
- `cargo check` / `cargo build` 一次通过、无警告；`cargo test` 3/3
- 无头渲染 + DOM 断言：失败时结果区 `display:none`、取消时状态条为中性样式、
  成功时结果区可见（共 7 项断言全过）
- 引擎回归 `工具/run_checks.py` 3/3

# 引擎异常兜底加固（2026-10-01）

## 现象

引擎（`--noconsole` 打包的 exe）在个别异常路径上会弹出
`Failed to execute script 'engine'` 对话框，进程停在那里等人点关闭；
而外壳正在等这个进程退出 —— 用户看到的就是「排课卡住不动」。

## 复现（已复现）

把引擎的 stdout 接到一个提前退出的读取方（例如 `engine.exe … | head -1`）：
管道读端关闭后，`engine.py` 的 `elog()` 里那句没有保护的 `print(..., flush=True)`
抛 `OSError: [Errno 22] Invalid argument` → 变成未捕获异常 → PyInstaller 弹模态框。

```
python 复现脚本/guard_test.py "…/engine/dist/engine.exe"
python 复现脚本/pipe_ab.py   "…/engine/dist/engine.exe"     # 管道关闭 vs 读到 EOF 的耗时对照
```

## 修复

1. `engine.py`：新增 `eout()` / `eerr()`，`elog()` 改走 `eout()`；**输出失败一律就地忽略**
2. `engine.py`：`__main__` 加兜底 `_emergency()`，任何异常都落成 `status.json`(code=2) 后正常退出
3. `engine.py`：退出前 `_detach_streams()`，避免解释器收尾时再 flush 一次已失效的输出流
   （否则进程退出码会变成 120）
4. `scheduler/data/load.py`：输入目录读不到 / `input.xlsx` 打不开 → 转成 `DataError`，给可照做的提示

## 回归结果（2026-10-01 实测，5 个场景全过）

| 场景 | 修复前 | 修复后 |
|---|---|---|
| 输入目录不存在 | 「引擎内部出错…请附错误编号 E-…」 | 1.5 s：「读不到输入目录「…」：系统找不到指定的路径。请确认该目录存在…」 |
| 目录里没有 input.xlsx | 同上 | 1.4 s：「输入目录里没有 input.xlsx」 |
| input.xlsx 被占用 / 损坏 | 同上 | 1.4 s：「打不开「input.xlsx」…请先关闭正在打开该文件的 Excel」 |
| **输出管道被提前关闭** | **弹模态框，进程不退出** | 正常退出，退出码 0，`status.json` 照常写出 |
| 无解数据（少 1 位语文教师） | — | 1.4 s：「至少需要 13 位「语文」教师…当前只有 12 位」 |

## 一条测量坑（别把「慢」当成「卡住」）

在 WorkBuddy 执行沙箱里跑打包后的 exe，**单次启动 + 收尾可能有约 50 秒的固定开销**
（PyInstaller onefile 解包 105 MB、退出时再删掉临时目录）。实测 `pipe_ab.py`：
关闭管道与读到 EOF 两种方式的退出耗时**一致**（均约 54 秒，退出码 0），
说明慢与管道无关，是沙箱的文件操作开销。

所以判定「弹框」的标准不是"慢"，而是：**给足超时后进程仍然不退出**。
（本机实际使用时的启动开销约 4 秒，见 `%APPDATA%\排课助手\logs\` 的时间戳。）

## 问题 1：「信息课」被判为没有对应老师

**现象**
在「课时标准」里新增一门课（学科名写「信息课」，非选考周课时 1，和体育/艺术一样不需要显示教师），
结果排课直接失败。

**实测（可复现）**
用仓库合成数据，在「课时标准」末尾追加一行 `信息课 / 0 / 1 / 0 / 0`，跑引擎：

```
status.json → code=2   方案数=0
message: 数据校验未通过：班级 C01 的「信息课」没有可用任课教师
         （「教师」sheet 中任教学科为「信息课」的教师为 0 人），无法排课
```

引擎在**阶段 2 数据校验**就失败（`engine.log` 显示 `+0.0s`），根本没进求解。

**定位**

- 白名单：`engine/scheduler/data/load.py:17`

  ```python
  NO_TEACHER_SUBJECTS = {"体育", "体育活动", "艺术", "音乐", "美术", "信息技术",
                         "通用技术", "心理", "班会", "研究性学习", "校本课", "自习"}
  ```
- 抛错处：`engine/scheduler/data/validate.py:40-44`

  ```python
  if not cands:
      raise DataError(
          f"班级 {c.class_id} 的「{c.subject}」没有可用任课教师"
          f"（「教师」sheet 中任教学科为「{c.subject}」的教师为 0 人），无法排课")
  ```

**根因**
白名单是**学科名的精确字符串匹配**。名单里已经有「信息技术」，但没有「信息课」／「信息」。
于是「信息课」被当成"需要任课教师"的学科 → 候选教师为空 → 阶段 2 抛致命 `DataError`。

实测确认：

| 学科名 | 在白名单里 | 结果 |
|---|---|---|
| 信息技术 | ✅ | 不需要教师，正常 |
| 信息课 | ❌ | **整套排课失败** |
| 信息 | ❌ | **整套排课失败** |

**期望**
1. 学校填的学科名会有各种写法，靠"猜全所有别名"兜底不可靠。建议二选一：
   - 做**归一化/别名表**（`信息` → `信息课` → `信息技术`），或改成包含关键字匹配；
   - 更稳的做法：在「课时标准」里加一列 **「是否需要教师」**（是/否，留空按默认），让学校显式声明。
2. 报错要能照做，例如：
   "「信息课」在教师表中没有对应教师。若这门课不需要教师（信息、心理健康、书法、劳动等），
    请把学科名改成 ……，或联系我们加入不需要教师的名单。"

**影响面**
任何非标准写法的"不需要教师"课程（信息课、书法、劳动、心理健康、生涯规划…）
都会把整套课表卡死，而用户看不出为什么。

**验收标准**
课时标准里加一门「信息课」（无对应教师），排课照常跑完；课表里显示"信息课"，且不含教师名。

## 问题 2：「特殊要求」的约束被忽略

测试时在界面「② 特殊要求」输入：

```
1.非物理选科班每周安排一节物理，非政治选科班每周安排一节政治
2.教师T30所教授的班级其中一个必须是C05
```

**实测结论**（把每一行单独喂给解析器 `_parse_teacher_constraints`）：

| 输入 | 解析结果 | 实际行为 |
|---|---|---|
| `T30教C05数学` | 成功 | ✔ 正常 |
| `T30=C05数学` | 成功 | ✔ 正常 |
| `张三教五班数学` | 成功 | ✔ 正常 |
| `1.T30教C05数学` | 空 | △ 只进"无法解析"告警 → **被忽略** |
| `1、` / `1）` / `(1)` / `①` / `- ` 前缀 | 空 | △ 同上 |
| `T30教C05`（漏写学科） | 空 | △ 同上 |
| `1.非物理选科班每周安排一节物理…` | 空 | ★ **完全静默丢弃，连告警都没有** |
| `2.教师T30所教授的班级其中一个必须是C05` | 空 | △ 进"无法解析"告警；**语义本身也不支持** |

### 2a 语法层（最可能是本次的直接原因）：行首编号会破坏解析

用户习惯像记笔记一样写「1. 2.」，但 `load.py:241` 只剥离了 `指定` `：` 和空白：

```python
line = re.sub(r'^[指定：\s]+', '', line)
```

没有处理 `1.` `1、` `1）` `(1)` `①` `- ` 这类列表标记。
于是 `1.T30教C05数学` 里第一个「教」之前的部分变成 `1.T30`，匹配不到教师 → 整行丢弃。

**建议**：解析前先剥掉行首列表标记，例如

```python
line = re.sub(r'^\s*(?:[（(]?\d+[）).、:：]?|[-*•]|[①-⑳])\s*', '', line)
```

建议同时补一条单测（`1.` 前缀必须能解析成功），这个坑很容易再犯。

### 2b 语义层：「T30 所教班级中必须有一个是 C05」引擎没有这种表达

现有**只支持一种语义**——「某教师教某班某科」：把 (班级, 学科) 的任课教师收缩为 1 人并锁定
（`load.py:520-533`）。而"某教师的带班集合里必须包含 C05"是**另一类约束**
（教师—班级的存在性/基数约束），模型里没有对应变量或约束 —— 属于**功能缺口**，不是顺手能修的。

**需要产品决策**：
- 这类"老师的班必须包含某班"的需求在校内常见吗？
- 若常见 → 需要新建模（引入"教师是否带某班"的布尔变量 + 基数约束）；
- 若个别 → 用现有语法近似：填 `T30教C05数学`（把 C05 的数学固定给 T30）。
  注意语义是**"指定"**，不是"至少一个"，两者不等价。

### 2c 静默层：不含「教」或「=」的行连告警都没有

`load.py:243-248`：

```python
if not m:
    # 只有「看起来像教师指定」（含 = 或 教）才计入未解析，
    # 否则「年级：高二」「测试用例」这类普通说明会被误报。
    if re.search(r'[=教]', line):
        unparsed.append(line)
    continue
```

所以第 1 条那种"非物理选科班每周安排一节物理"被**静默丢弃**。

> 顺带说明：这类"某选科组合每周加一节某课"**其实可以用数据表达**——
> 在「课时标准」里把该学科的「非选考周课时」设成 1 即可（`load.py:362` 按班级选科决定用选考/非选考课时）。
> 但用户不会知道，而引擎既不解释也不提示。

**建议**：把无法识别的特殊要求统一收集，写进 `status.json` 的 `warnings`，
并区分两种话术：
- 「这一行语法看不懂」（附正确格式示例）
- 「这一类要求（如 XX）当前不支持」（给出支持清单）

**验收标准**
- `1.T30教C05数学` 能正确生效；
- 输入不支持的约束时，结果面板明确告知"这条没生效、原因是什么"；
- 支持的约束类型在界面/文档里有清单。

## 问题 3：前端增加进度条

**现状（已确认）**

- 引擎**已经在输出阶段进度**：`engine/engine.py` 每次 `elog()` 都往 stdout 打一行，
  形如 `阶段1/5: 加载输入文件...`、`阶段4/5: 求解排课方案...`。
- 但**外壳拿不到实时输出**：`src-tauri/src/main.rs:663-694` 是
  `loop { try_wait() }`，**退出之后才 `read_to_end(stdout/stderr)`** —— 中间没有流式处理。
- 前端没有进度元素：`ui/index.html` 只 `setStatus('running', '正在排课，请稍候…（约需 3 分钟…）')`，
  `ui/style.css` 里搜不到 progress 相关样式。
- `main.rs` 全文件**没有任何 `emit`**（也没引入 `tauri::Emitter`）→ 外壳从未给前端发过事件。

**建议做法**

1. **外壳**：spawn 后**立刻起线程**把 stdout/stderr 逐行读走。
   （现在这种"退出后才读"还隐含一个隐患：引擎输出超过管道缓冲区（Windows 约 4–64KB）时，
   子进程会阻塞在写操作上，表现为"卡住"。目前日志量小没触发，但加了进度输出就会放大。）
2. **外壳**：从行里解析 `阶段N/5`（以及后面的"方案 i/N"），
   用 `app.emit("scheduler-progress", payload)` 推给前端，`payload` 建议含
   `stage` / `percent` / `message` / `elapsed_sec`。
3. **引擎（可选，为了粒度更细）**：`scheduler/solver/solve.py:193`
   `for i, (pname, weights) in enumerate(profiles):` 循环里，
   在 `solver.Solve()` 前后各打一行 `方案 i/N 求解中…` / `方案 i/N 完成`。
   否则最长的第 4 阶段（约 180 秒）进度条只能干等。
4. **前端**：`listen('scheduler-progress', ...)` 更新进度条。
   阶段 1–5 可映射到 5%~85%，最后 85%~100% 留给导出。

**验收标准**
排课过程中能看到进度（至少能看出"第几阶段 / 第几套方案"），不再是一行静态文字干等 3 分钟。

## 问题 4：课表单元格内「学科 + 教师」换行

**现象**
希望最终课表每个格子里：**上面学科、下面换行写该节课的教师姓名**。

**现状（已确认）**

- 课表网格**故意只写学科**：`engine/scheduler/export.py:62-71` 的 `_grid_rows()` 取
  `plan.grid[(班级, 日, 节)]`，值就是学科名。`export.py:128-129` 有注释说明原因：
  *"课表网格保持纯学科（校验器依赖它），任课信息单独出 sheet"*。
- 任课信息目前是单独 sheet：`任课表N`（`export.py:136-180`，班级 × 学科 → 教师姓名）。

**改动影响面（⚠️ 重点）**

1. `export.py:_grid_rows()` → 单元格改成 `f"{学科}\n{教师姓名}"`，
   同时 `Alignment(wrap_text=True)`，并适当调行高，否则第二行显示不全。
2. **`engine/verify_hard.py:189-220` 会把单元格里的字符串直接当成学科名**
   （`grid[(cur, d, per)] = cells[i]`），用来校验 H1–H5。
   一旦单元格变成"学科\n教师"，**所有硬约束校验都会误判**，必须同步改成"取第一行作学科"。
   这是最容易漏、也最容易把校验器搞坏的耦合点。
3. `NO_TEACHER_SUBJECTS`（体育/艺术/信息课…）与「自习」格子**不要**写教师行。
4. PDF 用的是同一个 `_grid_rows()`（`export.py:242`），会一起变化 ——
   需确认 PDF 也要教师名，以及 PDF 表格行高能否容纳两行。
5. 建议保留 `任课表N` sheet（教务可能还要按班级看任课）。

**验收标准**
- 课表格子里学科与教师分两行，不重叠、不截断；
- `python verify_hard.py <输入目录>` 校验全部通过（H1–H5 无误报）。

## 附：排查时顺带发现（不算本次问题，供参考）

1. **外壳读 stdout 的时机**（同问题 3 第 1 点）：退出后才 `read_to_end`，
   输出量大时子进程会被管道写满阻塞。
2. **两套校验逻辑不一致**：`engine/validate_input.py`（选完文件时的预检）与
   `engine/scheduler/data/validate.py`（引擎阶段 2）是各自独立实现的。
   预检不认 `NO_TEACHER_SUBJECTS` 白名单、也不查"某学科有没有教师"，
   所以问题 1 那种情况**预检通过、点开始排课才失败**。建议两处共用同一份判定逻辑。

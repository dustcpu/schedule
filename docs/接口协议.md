# 排课助手 — 外壳 ↔ 排课引擎 接口协议

> **协议版本**：v1.2（输入目录补记 hard_limits.json，新增可选结构化约束文件与围栏块约定）
> **日期**：2026-10-03
> **适用范围**：排课助手 Tauri 外壳 与 排课决策引擎（Python）之间的所有对接
> **核心原则**：三个人分头开发，本文件是唯一合同。任何一方要改协议，必须先改本文件并升版本号，通知另外两人，双方同步后再合并。

---

## 1. 架构

- **外壳**：Tauri 2（Rust 后端 + 原生 HTML/CSS/JS 前端），最终打包为 NSIS 安装版 + 绿色便携版。
- **引擎**：Python 编写，PyInstaller 打包为单个 `engine.exe`。
- **集成方式**：Tauri sidecar 机制。外壳在运行时静默调用内嵌的 `engine.exe`，用户无感知。
- **用户视角**：桌面上一个图标，点开 → 上传 xlsx → 填写特殊要求 → 点「开始排课」→ 得到 Excel + PDF 结果（含多套方案）。全程没有第二个窗口弹出。

---

## 2. 调用方式

用户每点一次「开始排课」，外壳启动一次引擎进程：

```
engine.exe <输入目录> <输出目录> <任务ID>
```

| 参数    | 类型   | 说明                                                        |
| ----- | ---- | --------------------------------------------------------- |
| 输入目录  | 绝对路径 | 外壳在调用前创建好，里面已放好 `input.xlsx` 和 `requirements.txt`         |
| 输出目录  | 绝对路径 | 外壳在调用前创建好（空目录），引擎把结果写这里                                   |
| 任务 ID | 字符串  | 外壳生成的唯一标识（如 `20260920_153012_ab12`），引擎原样回写到 `status.json` |

**调用约束**：

- 外壳通过 `std::process::Command` 启动进程，捕获 stdout / stderr 用于日志。
- 引擎进程**不允许弹出任何 GUI 或控制台窗口**（PyInstaller 打包时用 `--noconsole` / `--windowed`）。
- 外壳设置超时：**10 分钟**。超时后强杀进程，提示用户"排课超时"。
- 外壳**一次只跑一个任务**，不并发调用。
- 引擎不要自己再开子进程或后台线程做持久服务，跑完就退出。

## 3. 输入目录结构

外壳在调用前，会在输入目录放置以下文件（v1.2 起为"两个必选 + 两个可选"）：

| 文件名 | 必须/可选 | 格式 | 说明 |
| --- | --- | --- | --- |
| `input.xlsx` | 必须 | Excel 2007+ (.xlsx) | 用户上传的原始数据。**外壳不解析其内部结构**，sheet 名、列名、行数由算法团队与用户约定。 |
| `requirements.txt` | 必须 | UTF-8 纯文本 | 用户在界面文本框里填写的特殊要求，外壳原样写入，不做任何加工。**v1.2**：其中允许出现 ` ```json … ``` ` 围栏块（结构化约束，见 3.1）。 |
| `hard_limits.json` | 可选 | UTF-8 JSON | **v1.2 补记**（外壳自 v0.1.5 起实际已在写，此前协议漏记）：设置页的作息/固定课/连堂/软约束权重/求解参数。引擎有则覆盖、无则用默认值。 |
| `structured_requirements.json` | 可选 | UTF-8 JSON | **v1.2 新增**。结构化额外约束（约束转换器产出，schema 见 `docs/约束能力清单.md`）。引擎有则解析，无则忽略。 |

**约定**：

- `requirements.txt` 必须是 **UTF-8 无 BOM**。
- 引擎应只读取上述文件，忽略目录里其他可能的外壳临时文件。
- 引擎不要修改输入目录里的任何文件。
- 引擎自己的临时文件放到系统 temp 目录，不要放到输入/输出目录。

### 3.1 结构化约束（v1.2 新增）

- **两条进入通道**（内容同构，可同时存在，引擎合并去重）：
  1. 输入目录的可选文件 `structured_requirements.json`；
  2. `requirements.txt` 里的 ` ```json {"version":1,"constraints":[…]} ``` ` 围栏块
     （用户把转换器的输出整段粘贴进「特殊要求」框即可，外壳零改动）。
- **schema**：`{"version": 1, "constraints": [{"type": …, …}]}`，支持类型与字段
  以 `docs/约束能力清单.md` 为准（v1 共 5 类：assign_teacher / teacher_unavailable /
  teacher_no_double_day / class_unavailable / teacher_max_classes）。
- **引擎行为**：逐条独立校验；不合法（未知 type、教师/班级不存在、天数节次越界等）
  只丢弃那一条并写 `warnings`，**绝不能整体失败，也不允许静默丢弃**；
  合法条目逐条以「结构化约束已生效：……」写 `warnings` 回显。
- **兼容性**：两个可选文件/围栏块都不存在时，引擎行为与 v1.1 完全一致；
  **外壳无需任何改动**（外壳继续只写 input.xlsx + requirements.txt + hard_limits.json）。

## 4. 输出目录结构

引擎跑完后，必须在输出目录生成且**仅生成**以下三个文件：

| 文件名           | 必须/可选 | 说明                     |
| ------------- | ------- | ---------------------- |
| `result.xlsx` | 必须      | 排好的课表 Excel，**多 sheet 结构**，每套方案一个 sheet（见 4.1） |
| `result.pdf`  | 必须      | 排好的课表 PDF，**多页**，每套方案占一页或多页（中文不能乱码/方块） |
| `status.json` | 必须      | 执行状态、警告与方案列表，格式见第 5 节       |

**约定**：

- 所有文件在引擎进程退出前必须**完整写入并关闭句柄**，外壳才会去读。
- 输出目录里**不允许**残留 `.tmp`、`.crdownload`、`__pycache__` 等中间文件。
- 文件名固定为上述三个，不要加日期、任务 ID 前缀（外壳自己按任务归档到用户选的输出目录）。
- PDF 必须嵌入中文字体（reportlab 注册思源黑体/文泉驿，或 weasyprint 指定系统字体）。

### 4.1 多解输出（v1.1 新增）

排课引擎需要生成 **3–8 套不同的可行方案**（多解），而不是单套。交付格式：

**result.xlsx**：
- 每个方案一个 sheet，sheet 名按方案编号命名：`方案1`、`方案2`、`方案3`……
- 第一个 sheet 固定为 `总览`：列出所有方案的简要对比（编号、方案名、评分/满足度、关键特点），方便用户一眼比较。
- 每个方案 sheet 的内部结构（列名、行数）由算法团队自定，外壳不解析。

**result.pdf**：
- 第一页为总览（与 xlsx 总览 sheet 对应）。
- 之后每个方案占一页或多页（课表内容多就分页）。
- 每页页眉标注"方案 N：<方案名>"，方便翻页查找。

**方案数量**：引擎应尽量给出 3–8 套；如果约束太严只排出 1–2 套，允许少给，但必须在 `status.json` 的 `plans` 里如实列出实际数量，并在 `warnings` 里说明"约束过严，仅生成 N 套方案"。

## 5. `status.json` 格式

UTF-8 无 BOM，结构如下：

```json
{
  "task_id": "20260920_153012_ab12",
  "code": 0,
  "message": "排课完成，共生成 5 套方案",
  "plans": [
    {
      "index": 1,
      "name": "均衡方案",
      "score": 95.5,
      "note": "各班级课时均衡，教师负担均匀"
    },
    {
      "index": 2,
      "name": "紧凑方案",
      "score": 88.0,
      "note": "上课时间集中在周一至周四，周五空出"
    }
  ],
  "warnings": [
    "教师张三 周二第3节 与『高数A』冲突，已调整为周五第5节",
    "教室 B203 容量 30 人，选课班级 35 人，建议换大教室"
  ]
}
```

| 字段         | 类型        | 说明                                                                        |
| ---------- | --------- | ------------------------------------------------------------------------- |
| `task_id`  | string    | 原样回传外壳传入的任务 ID                                                            |
| `code`     | int       | **0** = 完全成功无冲突；**1** = 成功但有警告（`warnings` 非空），外壳仍应展示结果；**2** = 失败，未生成可用结果 |
| `message`  | string    | 一句话中文总结，例如"排课完成，共生成 5 套方案"、"数据缺失：教师表为空"                                 |
| `plans`    | array     | **v1.1 新增**。方案列表，每个元素见下表；无方案时为空数组 `[]`                                   |
| `warnings` | string[]  | 每条一个警告；无警告时为空数组 `[]`                                                      |

**plans 数组每项字段**：

| 字段      | 类型     | 说明                          |
| ------- | ------ | --------------------------- |
| `index` | int    | 方案编号，从 1 开始，与 xlsx sheet 名 `方案N` 对应 |
| `name`  | string | 方案名（简短中文，如"均衡方案"、"紧凑方案"）   |
| `score` | float  | 方案评分/满足度（0–100），无评分引擎可填 0   |
| `note`  | string | 一句话说明本方案的特点或取舍             |

**关键规则**：业务错误（数据不对、排不出来、部分冲突）**一律通过 `code=2` 或 `code=1` + `warnings` 表达**，不要用进程退出码表达。

## 6. 进程退出码

`engine.exe` 的进程退出码约定：

| 退出码 | 含义                                                 |
| --- | -------------------------------------------------- |
| `0` | 进程正常退出（无论 `status.json` 里 code 是 0/1/2，进程退出码都应为 0） |
| 非 0 | 进程级错误：崩溃、未捕获异常、参数错误、无法创建输出文件等                      |

**外壳判断逻辑**：

1. 先看进程退出码 → 非 0 = "引擎异常崩溃"，读 stderr 展示给用户。
2. 退出码为 0 → 读 `status.json`，按 `code` 字段决定展示成功/警告/失败。

也就是说：**外壳不猜业务结果，业务结果一律以 `status.json` 为准。**

---

## 7. 文件与编码约定

- 所有文本文件（`requirements.txt`、`status.json`）统一 **UTF-8 无 BOM**。
- Excel 用 `openpyxl` 写 `.xlsx`，**不要**写老的 `.xls`。
- 路径参数可能包含空格、中文、反斜杠，引擎按字符串原样使用，不要自己做 shell 转义。
- 引擎除输出目录外，**不要写任何位置**（不写注册表、不写用户目录、不写安装目录）。
- 引擎不联网、不发遥测、不读无关文件（符合隐私要求）。

## 8. 错误与边界情况

| 情况                         | 引擎行为                                            |
| -------------------------- | ----------------------------------------------- |
| `input.xlsx` 打不开/sheet 缺失 | `code=2`，`message` 写明哪个文件哪一行错                   |
| 数据不足，排不出任何课                | `code=2`，`message` 说明缺什么（例如"教师表为空"）            |
| 部分冲突无法完全解决                 | `code=1`，`warnings` 列出冲突项，`result.xlsx/pdf` 仍输出 |
| 约束过严，只排出 1–2 套方案           | `code=1`，`warnings` 说明"约束过严，仅生成 N 套方案"，`plans` 如实列出 |
| 用户文字要求无法解析                 | 忽略该条要求，写一条 warning，不要整体失败                       |
| 结构化约束某条不合法（未知 type/实体不存在等） | **只丢弃那一条**并写 warning 说明原因；其余条目照常生效               |
| 结构化约束互相冲突导致无解              | 能预判的（如全员禁连堂、教师带班超上限）`code=2` 并说明该怎么改；不能预判的走 INFEASIBLE 提示 |
| 超过 10 分钟                   | 外壳强杀进程，引擎无需自行处理                                 |
| 输出目录不可写                    | `code=2`，`message` 说明权限问题                       |

## 9. 版本与兼容性

- 本文件头部的版本号就是协议版本。
- 未来升级协议时（比如加参数、改文件名、加 status 字段）：
  1. 改本文件，版本号 +0.1
  2. 通知另外两人
  3. 双方代码同步更新后再合并
- 过渡期可在调用命令里加一个 `--protocol v1` 参数，让老引擎和新外壳能识别彼此；本草案暂不加，等真正要升级时再加。

## 0. 已确认口径（2026-09-21）

> **走班范围：除体育、艺术类课程外，其余课程大部分不走班。**

即语数外、理化生、政史地等主要科目按**行政班**固定上课；只有体育、音乐、美术等涉及走班。

**建模影响**：

| 约束 | 原设想（全面走班） | 现口径 |
|---|---|---|
| H1 行政班不冲堂 | 需处理行政班与走班组嵌套 | **主体逻辑**，覆盖绝大多数课时 |
| H7 走班组同步 | 所有选考科目都要同步 | **仅体育/艺术**需要 |
| H11 学生不冲堂 | 按学生级校验，规模剧增 | **仅体育/艺术**需校验，规模可控 |
| H22 教学班容量 | 大量教学班 | 仅体育/艺术教学班 |

**结论**：先把**行政班为主的经典高中排课**做扎实，体育/艺术走班作为**附加约束组**单独处理，不建全走班模型。文献依据见 `参考资料/03-走班制与新高考.md`。

## 1. 定位与边界

- 本文是「排课助手」Tauri 桌面框架内、排课引擎的**需求规格**：引擎读到什么、必须满足哪些约束、如何打分、如何输出多解。
- 框架主线是 **Tauri 桌面 + Python sidecar 引擎**（单用户、离线）。`schedule/` 原 README 里声明的 web 技术栈（Vue/FastAPI/PostgreSQL/Redis/Docker、多用户、拖拽编辑）**不采用**。
- 约束编号沿用 **H（正式课硬）/ S（正式课软）/ D（值班硬）/ O（值班软）**，另列 **G（流程保障）**。

## 2. 四条核心需求

| # | 需求 | 引擎承接方式 |
|---|---|---|
| 1 | 支持大量个性化硬/软约束（教师固定休息日、特定课程必须上午、教师不同时上两门课、不排早读、不带高三、不连上四节等） | 硬约束进求解器（见 §5/§7），软约束进打分（见 §6/§8） |
| 2 | **决策支持模式**：一次生成 3–8 套满足全部硬约束的备选课表，而非单一最优解 | 接口协议 v1.1 已要求多解输出；用不同目标权重/随机种子/多样性约束枚举 |
| 3 | 人工审核与编辑：拖拽调整后自动重新检测冲突并给原因 | 一期不做拖拽；冲突检测逻辑由独立校验器承担（见 §9 G02） |
| 4 | 新高考走班（3+1+2 / 6 选 3）下的分层走班排课 | **已收敛口径**：仅体育/艺术走班，其余按行政班（见 §0）。对应 H7/H11/H22 |

**明确不做**：学生选课过程、成绩管理、学籍管理。

## 4. 约束编号规则与权重上限

- 前缀：**H** 正式课硬约束（违反即无解）；**S** 正式课软约束（加权计分，权重 0 = 关闭）；**D** 值班/早读/静校/晚自习硬约束；**O** 值班软约束；**G** 流程保障。
- 编号确认后**冻结**，新增只能按顺序追加，不得插入或改号。
- **权重硬性上限 100**（软约束惩罚值）。原因：未排入一节课的惩罚是 **10000**、违反被放宽的硬约束是 **1000**，软约束总代价必须永远 < 1000，否则求解器会"理性地"丢一节课去换软约束达标。
- **H1 / H2 / H3 / H11 是物理约束，永不可放宽**（一位教师不能同时在两间教室、一间教室不能同时容纳两班、一个学生不能同时上两门课）。
- 无解时只给**最小放宽候选**，未经用户确认不得擅自放宽任何硬约束。

## 10. 输入数据模型（映射到框架）

外壳当前传入引擎的文件为 `input.xlsx` + `requirements.txt` + `hard_limits.json`（后两者由 `main.rs` 生成）。约束目录对应到输入载体如下：

| 载体 | 承载的约束/数据 |
|---|---|
| `input.xlsx` | 聘任表（→H8）、教师禁排时段（→H4）、固定时段/班会/自习（→H5）、走班选科名单（→H11）、场地与容量（→H3/H22）、特殊班型（→H21）、具名安排（→H20）、值班资格（→D2） |
| `hard_limits.json` | 时间安排、固定课程、班级设置（文理/新高考政策）、连堂规则——是 H5/H6/H15/H21 的一个**可配置子集**，由设置页维护 |
| `requirements.txt` | 用户自然语言特殊要求；引擎能解析的转成约束，无法解析的忽略并写 warning |

**建议 `input.xlsx` 至少含 5 个 sheet**：班级表（班号/文理/人数/选科组合）、教师表（姓名/科目/是否班主任/角色）、任课安排表（班级+科目+教师+周课时，核心）、教师禁排表（教师/星期/节次）、教室表（教室/容量/类型，可选）。

## 11. 待澄清问题（引擎需做成可配置项，未确认前用默认值）

1. ~~**走班模式**~~ → **已确认（§0）**：仅体育、艺术类走班，其余按行政班。仍需确认：体育/艺术是**按班分组**还是**学生自由选项目**？
2. ~~**走班范围**~~ → **已确认（§0）**：范围收窄至体育/艺术。仍需确认：是整年级一起走，还是几个班为一组？体育场地能同时容纳几个班（H3/H22）？
3. **排课单元**：哪些课是 `single`（整班）、哪些是 `group`（走班组）？选科名单以什么格式导入？
4. **学生不冲堂（H11）**：是否启用？**按 §0 口径，仅需在体育/艺术时段校验**，模型规模可控。仍需确认：学生是自由选项目（需 H11）还是按班分组（不需要 H11）？
5. **节次结构**：上/下午各几节？是否有早读、静校、晚自习？各占几个节次、是否参与求解？
6. **单双周**：是否启用？单双周是两套独立课表还是同一套标注周次？
7. **教师固定休息日（H4）**：全校统一规则还是逐人登记？谁维护？
8. **不带高三 / 不排早读**：这类个人约定是硬约束还是软约束？
9. **连堂**：哪些学科必须连堂？是否允许跨午休？是否必须同场地？
10. **值班资格（D2）**：音体美信是否完全不参与三类值班？行政人员是否参与晚自习？
11. **晚自习次数（D15）**：多班教师采用 2–3 次，还是 1–3 次且优先 2 次？
12. **周日晚自习（D14）**：是否固定由班主任承担？
13. **候选方案差异化**：3–8 套方案希望如何差异化？（分别侧重教师满意度 / 主科上午 / 值班均衡）
14. **调代课**：教务处之外是否需要申请调代课？是否纳入一期？

## 12. 求解器实现要点（算法种子：`engine/reference/ly398565721/`）

参考求解器用 **OR-Tools CP-SAT** 建模，核心文件对应关系：

- `core/models.py` —— 数据模型：`LessonRequirement`（班级/科目/教师/周课时/资源）、`ScheduleInput`（班级、天数、节次、课节、固定/禁排时段）、`SolvedSchedule`（状态/课节/放宽候选）。
- `core/formal_solver.py` —— CP-SAT 建模：以 `(课节, 星期, 节次)` 为布尔变量；满足周课时守恒、班级/教师/资源不冲堂、禁排、连堂配对、日课量分级、半天制、数学/体育上限等（对应 H1/H2/H3/H4/H6/H12/H13/H14/H15/H16/H17）。
- `core/validate_formal.py` —— 独立校验器：不复用 CP-SAT 变量，从物化课节重新推导全部硬约束（对应 G02）。
- `core/duty_solver.py` / `validate_duty.py` —— 值班求解与校验（对应 D/O 约束）。
